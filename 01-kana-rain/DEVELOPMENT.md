# Development

Use [README](README.md) for setup and the full check sequence, [SPECIFICATION](SPECIFICATION.md) for the playable contract, [NOVELTY_BALANCE](NOVELTY_BALANCE.md) for admission transitions, and [LEARNING_DESIGN](LEARNING_DESIGN.md) for evidence and pedagogical limits. This handoff covers implementation and maintenance contracts.

See [TESTING](TESTING.md) for the current test inventory, functional coverage, verification results and prioritized gaps. Test counts are not a measured code-coverage percentage.

The app is static HTML, CSS and JavaScript. Source previews load `data`, `learner`, `audio`, `sfx`, `music`, `difficulty`, `novelty`, then `game`; the production bundle preserves that order. The game awaits `Learner.ready` before reading saved state. Keep the `window.KanaRain` module boundary (`generateRound`, `render`, `score`, `dispose` and session controls) available to integration tests. `score` decorates evidence; it is not a point-scoring system.

Preserve these runtime invariants:

- Schedule animation frames only for active play or countdowns. Pause, hidden tabs and disposal stop the loop; resuming starts with a fresh frame clock. Simulation and pending-input delays use active time.
- Cache field and sprite dimensions with `ResizeObserver`. Geometry reads during creation or resizing are legitimate; avoid repeated layout reads in the frame loop.
- Rebuild progress panels only when dirty and visible. Build the fixed sound pad once, then update its stage. Update HUD text and classes only when their visible values change.
- Animate decorative rain with transforms and freeze it outside active play. Preserve reduced-effects and viewport/safe-area behavior when changing visuals.
- Prepare feedback images only after the critical scene, in low-priority tasks. Keep preparation optional and decoded image references alive; never await it from input, scoring or the animation loop.

Persistence belongs to `src/learner.js`. Continue reading the legacy `jp-learner-v1` key while writing `jp-learner-v1:protected:v1`; retain schema-v2 exports and IndexedDB database `kana-garden` version 1 / store `learner`. Bootstrap unions compatible primary, checkpoint and legacy snapshots, then replays tab-owned write-ahead journals (`jp-learner-v1:pending:<writer>`). Timestamps/vectors select preferences only after checking facts; they never prove that evidence is complete. Schema-v1 migration keeps legacy aggregates without fabricating independent evidence. Preserve old attempts, exposures, retired-mode facets, earned rows, accuracy, historical point records and additive game-data fields when normalizing settings.

Attempt/exposure IDs are indexed for idempotency and rebuilt on import/reload; new IDs include a unique tab writer. Do not truncate ledgers; the bounded error log is a derived diagnostic. Game recording defers the individual learner save, updates related game data, then flushes together. Each flush synchronously journals immutable changes in its own key; Web Locks serialize canonical commits, and IndexedDB reads/merges/writes inside one native transaction. `pagehide` uses the same journal path without relying on an asynchronous callback completing before unload. Only the owner prunes acknowledged operations; without Web Locks journals remain available for replay, including after a crash. Never delete another active writer's journal. `_sync` is additive schema-v2 metadata: revision vectors deduplicate operations and reset/import generations prevent stale tabs resurrecting discarded data. Aggregate facts are rebuilt from the union of event IDs; accuracy/session deltas add once, rows/earned flags merge monotonically, settings change only when edited, and novelty rounds/seen/pause merge separately. Reconcile objects in place because the running game holds gameData and novelty references. Save status reflects successful writes/transaction completion; an older transaction cannot replace the latest failure state. Keep the in-memory/export fallback when both backends fail.

Consolidation may reuse a private normalized IndexedDB snapshot only after comparing its complete serialized content, including all event IDs, historical baselines and metadata. Revision vectors, timestamps or equal ledger lengths do not establish equality. The bounded memo contains only the current protected/legacy database entries; changed or malformed data takes the normal validation/recovery path. Prepared snapshots are commit-owned and never alias the mutable public learner state, so retaining one as the durable base avoids a redundant deep copy. Keep the independent memory copy and final reconciliation, including mutations while a transaction is pending. This optimization does not batch or postpone the synchronous write-ahead journal.

Asset regeneration is explicit and writes tracked outputs:

| Command | Purpose |
|---|---|
| `pnpm assets` | Extract/compress the garden and sprite masters using `scripts/prepare-assets.cjs`; review generated-image diffs. |
| `node scripts/prepare-runtime-audio.cjs` | Regenerate the compact lookup from the catalogue and approved source manifest. Add `--check` to verify it without writing. |
| `node scripts/build.cjs --check` | Validate the production plan, local references and audio correspondence without replacing `dist/`. |

Keep artwork masters/prompts and the complete audio manifests, recordings, licenses and provenance. The compact runtime lookup selects gameplay recordings; unused source recordings are not permission to discard provenance.

`scripts/build.cjs` owns the production allowlist. It emits the ordered runtime, inlines/rebases home-page styles, and copies the public pages and approved assets. Source CSS remains necessary for other public pages. Deploy the contents of `dist/`; building does not publish. Keep private exports, tests and artifacts outside the allowlist.

Coordinate packaging with `sw.js`: cache index.html once, inspect its runtime reference, then install either the production bundle or the source modules. Retain the CSS used by secondary pages and all unique audio files with bounded download concurrency. Keep release cache names synchronized with runtime/asset releases. Cache navigation destinations separately, preserve canonical page aliases, and normalize cached redirected HTML responses on offline navigation without dropping status or headers. A missing offline destination must not silently become another page.

Game analytics have a strict schema:

| Event | Game payload |
|---|---|
| `practice_start` | `practice_mode`: `hira`, `kata` or `review` |
| `practice_complete` | The same mode plus `completion_reason`: `timer_elapsed`, `hearts_lost` or `manual_finish` |

Start fires once when the initial countdown completes; pause/resume does not repeat it. Completion requires a started session; disposal alone emits nothing. The shared client also accepts `completed`, which this game does not emit. Keep consent/host checks and exact-key/enum validation in `assets/nihongo-analytics.js`. Page metadata uses approved routes without query strings/fragments and origin-only referrers. Never add responses, counts, item IDs or learner history to analytics payloads.

Useful focused checks are `pnpm test:performance`, `pnpm test:analytics`, and `pnpm test:katakana-bridge` (which includes cold-start, legacy-save and feedback regressions). `tests/input.browser.cjs` is exercised by `test:browser`. Run the README's complete sequence before release; CI runs Node tests, seven source browser suites, the build, `pnpm test:quick-wins`, `pnpm test:update` and `pnpm test:storage` against that build. All three build suites use ephemeral servers and reject stale build files. Browser suites use Playwright Chromium unless `PLAYWRIGHT_BROWSER_CHANNEL` selects an installed channel. Use disposable synthetic profiles, keep owned server ports free, and close contexts/servers after checks; offline tests intentionally exercise service workers.

The update suite uses the pinned historical release fixture, not the moving production domain. Keep its manifest/payload with the compatibility tests. It compares old ledger entries verbatim, per-kana aggregates and game settings across activation, and reads real localStorage/IndexedDB without forcing the game to save. During offline checks the test server also cuts connections, including browser-owned worker update requests that can escape page-level offline emulation. An expected failed install must not remove the old cache; successful activation must remove the old game cache while preserving an unrelated cache. Test artifacts stay in `tests/artifacts/update/`. This covers a controlled open-tab 1.10.1→candidate update in Chromium, not browser termination, concurrent tabs or every historical version.

The native storage suite deliberately fills localStorage and constrains the owned origin's IndexedDB quota through CDP. It waits for Chromium's cached write allowance to expire and requires a real `QuotaExceededError` from a native transaction; it never substitutes `setItem`, IndexedDB or save functions. Restart tests launch/reopen an owned disk profile and inspect storage before starting the game again. The pending-write case holds a real IndexedDB write transaction open in another page. UI scenarios observe application saves without forcing a flush; overlap scenarios deliberately submit 24 learner changes from two renderer processes at one deadline. Assertions require both sets of exact events, additive counters, earned rows and reload idempotency, including closing one tab while both commits are blocked and IndexedDB quota fallback. Temporary profiles created by that run are removed only after browsers close, with resolved-path containment checks. Disk hardware failure, OS power loss and forced process termination remain outside this coverage.

`pnpm test:mixed-version-storage` adds real old-runtime coexistence using the pinned 1.10.2 learner. Its blank localhost pages deliberately load learner modules only; these are persistence tests, not gameplay smoke tests. Old runtimes write `jp-learner-v1`; current code reads that key but writes only `jp-learner-v1:protected:v1` in localStorage and `kana-garden` v1 / `learner`. Keep reading both independent backends and the bounded checkpoint. Vectors suppress repeated operation deltas, never immutable facts or earned metadata. Snapshot joins derive known accuracy buckets from union events plus their historical remainder; opaque historical counters and completed-session lower bounds are retained without inventing missing session events. The checkpoint is best effort and must not abort the primary transaction. No tests may consume personal exports or launch personal browser profiles.

After publishing this protocol, fix incidents forward using a version that still reads the protected primary. A pre-1.10.4 rollback cannot read that key and may display stale legacy progress. Keep the same production origin; do not restore personal exports during a code-only release.

The player-facing import uses `Learner.previewImport(json)` for validation and a read-only summary, then `Learner.importProgress(json)` for additive application. It retains the current generation and journals the imported evidence and legacy baselines, including baseline-only imports. Keep current preferences, deduplicate immutable facts, reject conflicting IDs and unsafe object keys, and preserve earned access. The older `Learner.import(json)` replacement API remains separate for compatibility and explicit generation replacement. `pnpm test:import` exercises the actual file chooser, preview, cancellation, backup, native storage, quota fallback, reload and responsive controls with synthetic files only.

The optional `node tests/runtime-browser.benchmark.cjs` compares runtime counters against `KANA_RAIN_BASELINE_URL` or the current public release; it defaults to installed Chrome. Its public baseline changes after publication. Node persistence diagnostics measure CPU work and test doubles, not real IndexedDB disk latency. Browser/Lighthouse results also depend on browser, device, server and network conditions; do not attribute hosting latency or injected third-party script warnings to game code without isolating them. Avoid concurrent browser work while measuring. Reports/screenshots belong in ignored `tests/artifacts/`; private release evidence belongs in the repository's ignored `.release/` directory.

Keep the working tree focused on the current game, reproducible source assets, development tools and meaningful regression fixtures. Update the canonical documents above when behavior changes; use the changelog and Git history for past decisions rather than retaining parallel specifications or presentation decks. Periodically remove generated reports and obsolete local snapshots, while retaining the current deployment binding, a recent rollback and any files used by a running preview. A legacy-save fixture or compatibility branch is still necessary when it protects existing player progress.
